# 1주차 회고: 장애를 낼 수 있는 앱 (2026-10-16 ~ 10-19, Phase 0 포함)

> 작성일: 2026-10-23 (2주차 회고와 함께 소급 작성) · 장애별 상세 분석은 1주차 포스트모템 참고

## 한눈에 보기

**한 줄 평:** 업무 서버를 건드리지 않는 안전한 실습 환경을 만들었고, 일부러 장애를 낼 수 있는 앱과 구조화된 로그를 갖췄다.
첫 조사에서 "서버 로그가 정상인데 사용자는 실패하는" 장애를 직접 재현하고 원인을 확정했다. 이 발견이 2주차 설계(R3, R4)의 출발점이 됐다.

## 잘된 것

1. **업무 서버와 실습 환경을 분리한 결정.** 서비스 컨테이너와 포트·자원이 충돌할 걱정 없이 마음껏 실험했고, 망가져도 스냅샷으로 되돌릴 수 있다.
2. **처음부터 기계가 읽는 로그(JSON)로 설계.** 요청마다 번호(request_id)를 붙이고 응답 시간과 상태를 남겨서, 이후 모든 판단과 시험의 재료가 됐다.
3. **가설을 세우고 구분할 수 있는 관측을 추가한 뒤 재현.** "로그가 멈췄다"는 첫 판단이 틀렸다는 것을 시계열 집계로 바로잡았고, 가설 4개를 증거로 하나씩 채택·기각했다.
4. **DB를 멈추는 실험에서 에러 시그니처를 확보.** 예상한 "연결 거부"가 아니라 "이름을 못 찾음"이 나온다는 것을 알게 됐고, 이 표가 3주차 런북의 재료가 된다.

## 아쉬운 것

1. **비밀번호가 대화에 노출됐다.** 설정 파일(.env) 내용을 그대로 붙여서 비밀번호가 드러났고, 교체와 DB 재생성이 필요했다.
2. **DB 비밀번호의 특수문자가 접속 주소(URL)를 깨뜨려 앱이 재시작을 반복했다.** 접속 정보를 주소로 조립한 설계의 약점이었다.
3. **측정 도구가 실패를 한 종류로 뭉뚱그렸다.** 타임아웃, 연결 거부, 연결 끊김을 구분하지 못해 원인 추적이 한 번 막혔다.
4. **AI가 쓴 조사 보고서에 결론과 증거가 어긋난 부분이 있었다.** 검토 없이 믿었다면 틀린 결론("클라이언트가 끊은 연결에 워커가 묶였다")이 문서에 남았을 것이다.
5. **앱 코드에 숨은 결함을 한 주 동안 못 봤다.** 방문 수를 세는 쿼리가 행이 늘수록 느려지는 문제였고, 2주차에 발견됐다.

## 문제와 원인 (최신순)

| 문제 | 근본 원인 | 재발 방지 |
| --- | --- | --- |
| 포화 장애에서 서버 로그는 정상인데 사용자는 모두 실패 (10-19) | 처리 용량(약 2.2건/초)보다 요청(5건/초)이 많아 대기열이 쌓이고, 15초를 넘으면 서버가 처리하는 요청이 이미 포기된 요청이 됨 | R3(요청 감소), R4(프로브)로 사용자 관점에서 탐지 |
| 비밀번호 노출 (10-19) | 설정 파일 원문을 그대로 공유 | 비밀번호 교체, 값은 가려서 공유, 규칙에 "`.env` 미열람" 추가 |

| 권한 거부로 Docker 명령 실패 (10-19) | 그룹 변경이 이미 열린 세션에는 적용되지 않음 | 세션 재시작 |
| 환경 구축 중 8건 (10-16) | 커널 재시작 필요, snap 미설치, Git 브랜치·키 설정, 회사 레포 혼입, Tailscale 로그인 흐름 등 | 각 해결 방법을 트러블슈팅 기록에 남김 |

## 배운 것

1. **서버 로그의 200은 사용자의 성공이 아니다.** 서버는 쉬지 않고 일했지만 그 결과를 받은 사람은 없었다(throughput과 goodput의 차이).
2. **시계열 현상은 한 번 보지 말고 구간으로 본다.** 시작 시각을 기록하고 구간별로 집계해야 "멈췄다"와 "계속 일했다"를 구분한다.
3. **진단 명령은 에러를 숨기지 않는다.** 조용히 실패한 명령이 잘못된 결론으로 이어질 뻔했다.
4. **AI의 보고서는 결론이 아니라 증거 표를 기준으로 검증한다.**
5. **같은 "DB 장애"도 에러 모양이 여러 가지다.** 이름 해석 실패, 연결 거부, 시간 초과, 인증 실패를 구분하는 표가 런북의 바탕이 된다.

## 이때 부족했던 점 (2주차에서 보강됨)

- 협업 방식이 한 도구에서 섞여 있었다. 2주차 후반에 설계·검토(클라우드 세션)와 실행(Claude Code)으로 역할을 나눴다.
- 합격 시험이 없었다. 눈으로 로그를 따라가며 확인했다. 2주차에 자동화했다.
