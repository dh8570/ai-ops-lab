# AI 우선 4주 계획 (2026-10-27 ~ 11-27)

2026-11-17에 일정을 재조정했다(마감 11/27, 4일 연장). 남은 일(공개 링크, RAG 최소판, 저장 데이터 설명, 규칙 대 ML 최소 비교, 최종 문서, 시연)을 아래 일정에 맞춰 다시 짰다.

이 문서가 4주 계획의 **유일한 원본**이다. 다른 문서(CLAUDE.md, PROJECT_CONTEXT.md, README.md)는 이 문서를 가리키기만 한다.
용어는 [docs/glossary.md](../glossary.md)에 쌓는다.

## 목적

배우려는 것 세 가지:

| # | 질문 |
| --- | --- |
| 1 | 어떤 문제를 AI로 푸는가 |
| 2 | AI는 이 프로젝트에서 어떻게 동작하는가 |
| 3 | 데이터는 어디에 저장해 어떻게 쓰는가 |

서비스 완성도가 목적이 아니다. **AI 적용과 그 근거(채점표, 비교표)가 결과물이다.**

## 원칙

- AI 우선. 인프라 작업은 AI 단계를 막을 때만 최소로 한다.
- 매주 시작할 때 그 주의 "AI 질문 세 가지"를 정하고, 그 주의 일이 그 질문을 향하는지로 판단한다.
- 매주 결과물에 채점표나 비교표가 하나 이상 들어간다.
- 현미경 엔진(M2)은 목적의 AI 질문 2번(AI는 이 프로젝트에서 어떻게 동작하는가)을 깊게 파는 학습 트랙이며 A주에 끝났다. 층별 화면(M3~M5)과 토큰화 5단계(M1)는 이번 일정에서 제외한다(후속). 그 주의 필수 결과물은 질문 세 가지에 대한 채점표·비교표이며, 일정이 밀리면 학습 트랙을 먼저 줄인다.
- 일정이 밀리면 줄이는 순서: 규칙 대 ML 비교를 표 1개와 설명 문서로 축소, RAG 범위 축소. 이번 일정에서는 토큰화 5단계(M1), 현미경 화면(M3~M5), 에이전트, 마스킹 구현, Fig 3·4 갱신을 제외한다(현미경 엔진 M2-a·b는 완료, 화면은 후속). 범위 동결일은 11/22(점검일)이다.
- 모르는 용어와 내용은 질문하며 배운다. 새 용어는 docs/glossary.md에 쌓는다.
- 마스킹을 구현하거나 에이전트(tool calling)를 하게 되면 그 안전장치는 Opus, 나머지는 Sonnet.
- 탐험 사이트는 실제 파이프라인의 실행 기록을 보여 주는 뷰어이며, 사이트에만 있는 로직을 만들지 않는다. 화면의 값에는 증거 등급(실측, 계산, 설명용, 미확인)을 붙인다.
- 모델은 두 길로 쓴다: Ollama(서버 GPU, Q4 압축, 운영용: 장애 알림 요약)와 현미경 엔진(VM CPU, bf16 원본, 학습용: 모든 층의 값을 기록). 현미경 엔진은 알림 경로에 쓰지 않는다.

## A주 (10/27 ~ 11/5, 11/2에 연장) LLM이 장애를 분석하게 하기

LLM 알림(실패해도 기본 알림)이 11/2까지 끝나지 않아 11/5까지 연장했다. 채점표는 원래 B주 항목이었으나 연장 기간 안에 앞당겨 끝냈다(시나리오 15개, 사람 채점, docs/eval).

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | LLM은 입력을 어떻게 받아 무엇을 내놓나 (토큰, 읽을 수 있는 양, 속도) |
| 2 | 어떤 정보를 넣어야 원인을 맞히나 (프롬프트, 근거에 넣는 정보의 영향) |
| 3 | AI의 답을 어떻게 믿나 (지어낸 답, 실패 시 대체, 채점표와 사람 채점) |

### 할 일

- GPU 서버(controller1)에 Ollama를 설치하고, VM↔서버 통로 주소 10.97.0.1:11434에만 공개한다.
- 응답 시간 표를 만든다 (CPU 대 GPU, 콜드와 웜, 입력 크기).
- "알림 먼저, 분석 뒤따름" 여부를 숫자로 결정한다.
- 원문 로그를 AI에 보내지 않는 방식(M0: 숫자·건수·정해진 이름만 보내고 경로는 {id}로 정규화하며 예외는 종류만 보낸다)으로 민감 정보 노출을 막는다. IP·토큰·이메일을 치환하는 마스킹 구현은 이번 일정에서 제외하고 mask() 자리만 둔다.
- 런북 2~3개를 쓴다.
- LLM 호출과 알림 전송을 감시 루프 밖으로 옮긴다.
- LLM 실패 시 기본 템플릿을 보낸다.
- 탐험 사이트 척추(M0: 실행 기록 형식, 단계 페이지 틀, 설정 슬라이더, 색상 토글)를 만든다.
- 현미경 엔진(M2-a·M2-b: Qwen2.5-7B를 VM CPU에서 bf16으로 직접 계산해 모든 층의 값을 기록하고 공식 구현과 비교·검증)은 A주 중에 앞당겨 끝냈다. 사이트 연결(M2-c)과 층별 화면(M3~M5)은 이번 일정에서 제외한다(후속).
- AI 분석 품질을 장애 시나리오로 채점하는 도구(scripts/eval)를 만들고(시나리오 15개, 사람 채점 약 48칸, docs/eval), 프롬프트 개선 후보(v2, v3)를 사전에 정한 채택 기준으로 비교했다. 현재 운영 프롬프트(v1)는 근거에 없는 원인을 자주 쓰므로 운영 채널에서는 아직 AI 분석을 켜지 않는다.

### 완료 기준

- 장애 알림에 요약·원인 후보·확인 항목이 붙는다.
- Ollama를 멈춰도 기본 알림이 간다 (합격 시험 항목으로 자동화).
- 감시 루프가 AI 호출로 멈추지 않는다.
- 탐험 사이트에서 실행 하나가 단계별 페이지로 보인다(M0).
- 채점표(시나리오 15개)와 사람 채점 기록이 docs/eval에 있다.

## B주 (11/6 ~ 11/17) 프롬프트 개선, 그림자 모드, 공개 링크 설계

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | 프롬프트를 어떻게 바꾸면 AI가 덜 지어내나 (v2, v3 비교) |
| 2 | 후보를 어떻게 공정하게 비교하나 (보류 시나리오, 사전 채택 기준, 사람 채점) |
| 3 | 새 기능을 운영에 안전하게 붙이려면 (스위치, 그림자 모드, 시작 거부) |

### 할 일

- 프롬프트 스위치(LLM_PROMPT_VERSION, 기본 v1)와 그림자 모드(ANALYSIS_WEBHOOK_URL, AI 분석 알림만 별도 웹훅)를 운영 코드에 넣었다(PR #19, #20).
- 프롬프트 후보(v2, v3)를 보류 시나리오로 비교했다(v3 폐기, v2는 사람 정확성이 가장 높지만 "알 수 없음: 이유" 자리표시 문제가 있어 승격 보류).
- 공개 내보내기(정적 사이트)의 안전 모듈과 장애 기록 화면을 만들고 있다(진행 중. 조립과 배포는 C주).
- 원래 B주의 "RAG와 저장 데이터" 항목은 C주로 옮겼다.

### 완료 기준

- 프롬프트 스위치와 그림자 모드가 병합되었다. 그림자 모드를 켜서 장애 분석 기록을 모으는 일은 11/17에 시작한다.

## C주 (11/18 ~ 11/22) 공개 링크 1차, RAG 최소판, 저장 데이터, 규칙 대 ML(최소)

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | 런북을 어떻게 골라 주면 옮겨 적기가 줄어드나 (RAG 최소판) |
| 2 | AI 분석과 사람 판정을 어디에 어떻게 저장하나 (저장 데이터) |
| 3 | 규칙과 ML은 무엇이 다른가 (Isolation Forest 최소 비교) |

### 할 일

- 공개 링크 1차: 탐험 뷰어, 장애 분석 기록, 채점표, 그림. 호스팅은 이 레포의 gh-pages 브랜치에서 GitHub Pages로, 허용 목록에 있는 자료만 검사 게이트를 통과해 내보낸다.
- RAG 최소판: 런북을 원인 단위 조각으로 쪼개 근거 내용(예외 이름, 경로, 프로브 결과)으로 고르는 방식을 기존 채점표와 warm 기준으로 전체 런북과 비교한다. 규칙 번호로 런북을 고르는 방식은 효과가 없었다. 임베딩과 pgvector는 11/22에 시간이 있을 때만 한다.
- 저장 데이터 설명 문서(테이블 설계).
- 규칙 대 ML은 하루 안의 최소 비교(Isolation Forest 대 규칙, 안 되면 설명 문서).

### 완료 기준

- 공개 링크 1차.
- RAG 최소판 비교표.
- 저장 데이터 설명 문서.
- 규칙 대 ML 비교표 1개.

11/22는 점검일이자 범위 동결일이다. 이후 새 기능은 넣지 않고 문서, 시연, 버그 수정만 한다.
