# AI 우선 4주 계획 (2026-10-27 ~ 11-23)

이 문서가 4주 계획의 **유일한 원본**이다. 다른 문서(CLAUDE.md, PROJECT_CONTEXT.md, README.md)는 이 문서를 가리키기만 한다.
용어는 [docs/glossary.md](../glossary.md)에 쌓는다.

## 목적

배우려는 것 세 가지:

| # | 질문 |
| --- | --- |
| 1 | 어떤 문제를 AI로 푸는가 |
| 2 | AI는 이 프로젝트에서 어떻게 동작하는가 |
| 3 | 데이터는 어디에 저장해 어떻게 쓰는가 |

서비스 완성도가 목적이 아니다. **AI 적용과 그 근거(채점표, 비교표)가 결과물이다.**

## 원칙

- AI 우선. 인프라 작업은 AI 단계를 막을 때만 최소로 한다.
- 매주 시작할 때 그 주의 "AI 질문 세 가지"를 정하고, 그 주의 일이 그 질문을 향하는지로 판단한다.
- 매주 결과물에 채점표나 비교표가 하나 이상 들어간다.
- 현미경 엔진과 층별 화면(M2~M5)은 목적의 AI 질문 2번(AI는 이 프로젝트에서 어떻게 동작하는가)을 깊게 파는 학습 트랙이다. 그 주의 필수 결과물은 질문 세 가지에 대한 채점표·비교표이며, 일정이 밀리면 학습 트랙을 먼저 줄인다.
- 일정이 밀리면 줄이는 순서: M4·M5, M1, 규칙 대 ML 비교를 표 1개와 설명 문서로 축소, RAG 범위 축소. 점검일은 11/16이다.
- 모르는 용어와 내용은 질문하며 배운다. 새 용어는 docs/glossary.md에 쌓는다.
- 민감 정보 제거(마스킹)는 Opus, 나머지는 Sonnet. 에이전트(tool calling)를 하게 되면 그 안전장치도 Opus.
- 탐험 사이트는 실제 파이프라인의 실행 기록을 보여 주는 뷰어이며, 사이트에만 있는 로직을 만들지 않는다. 화면의 값에는 증거 등급(실측, 계산, 설명용, 미확인)을 붙인다.
- 모델은 두 길로 쓴다: Ollama(서버 GPU, Q4 압축, 운영용: 장애 알림 요약)와 현미경 엔진(VM CPU, bf16 원본, 학습용: 모든 층의 값을 기록). 현미경 엔진은 알림 경로에 쓰지 않는다.

## A주 (10/27 ~ 11/5, 11/2에 연장) LLM이 장애를 분석하게 하기

LLM 알림(실패해도 기본 알림)이 11/2까지 끝나지 않아 11/5까지 연장했다. 채점표는 LLM 알림 구현이 끝난 뒤 B주 초로 옮겼다.

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | LLM은 입력을 어떻게 받아 무엇을 내놓나 (토큰, 읽을 수 있는 양, 속도) |
| 2 | 어떤 정보를 넣어야 원인을 맞히나 (프롬프트, 마스킹의 영향) |
| 3 | AI의 답을 어떻게 믿나 (지어낸 답, 실패 시 대체. 채점은 B주 채점표에서) |

### 할 일

- GPU 서버(controller1)에 Ollama를 설치하고, VM↔서버 통로 주소 10.97.0.1:11434에만 공개한다.
- 응답 시간 표를 만든다 (CPU 대 GPU, 콜드와 웜, 입력 크기).
- "알림 먼저, 분석 뒤따름" 여부를 숫자로 결정한다.
- 마스킹(IP, 토큰, 이메일)을 만들고 테스트한다.
- 런북 2~3개를 쓴다.
- LLM 호출과 알림 전송을 감시 루프 밖으로 옮긴다.
- LLM 실패 시 기본 템플릿을 보낸다.
- 탐험 사이트 척추(M0: 실행 기록 형식, 단계 페이지 틀, 설정 슬라이더, 색상 토글)를 만든다.
- 현미경 엔진(M2-a·M2-b: Qwen2.5-7B를 VM CPU에서 bf16으로 직접 계산해 모든 층의 값을 기록하고 공식 구현과 비교·검증)은 A주 중에 앞당겨 끝냈다. 사이트 연결(M2-c)은 C주 M3에서 캡처 재생으로 한다.

### 완료 기준

- 장애 알림에 요약·원인 후보·확인 항목이 붙는다.
- Ollama를 멈춰도 기본 알림이 간다 (합격 시험 항목으로 자동화).
- 감시 루프가 AI 호출로 멈추지 않는다.
- 탐험 사이트에서 실행 하나가 단계별 페이지로 보인다(M0).

## B주 (11/6 ~ 11/11) 데이터, RAG, 채점표

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | AI용 데이터는 어디에 어떤 모양으로 저장하나 |
| 2 | 임베딩과 벡터 검색은 어떻게 비슷한 것을 찾나 |
| 3 | 찾아 넣은 지식이 답을 얼마나 좋게 하나 |

### 할 일

- 기존 Postgres에 pgvector를 추가한다.
- 테이블을 만든다: 장애 / AI 분석(프롬프트, 답, 모델, 시간, 토큰 수) / 사람의 판정(맞음·틀림) / 런북 조각과 벡터.
- 런북과 과거 장애를 검색해 프롬프트에 넣는다.
- RAG 전후를 비교한다.
- 장애 시나리오 5개로 채점표를 만든다(A주에서 이동).
- 토큰화 5단계(M1)는 시간이 남으면 한다.
- 현미경 엔진(M2-a·M2-b)은 A주에 끝났다.

### 완료 기준

- RAG 있음 대 없음 채점 비교표.
- 저장 데이터 설명 문서.
- 채점표 1개(장애 시나리오 5개).

(A·B주까지 마치면 목적의 세 질문 모두에 첫 답이 나온다. C·D주의 현미경 화면은 두 번째 질문을 더 깊게 판다.)

## C주 (11/12 ~ 11/17) 규칙 대 ML 비교(최소)와 현미경 화면

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | 규칙과 ML은 무엇이 다른가 |
| 2 | 어떻게 학습하고 평가하나 (잘못 울림, 놓침, 기준값) |
| 3 | 운영에 넣으면 무엇이 달라지나 (재학습, 데이터 변화) |

### 할 일

- 느린 성능 저하 장애를 주입하고 Isolation Forest와 규칙을 비교한다(비교표 1개로 축소).
- 현미경 화면 M3(임베딩, Prefill, 첫 토큰)을 미리 만든 캡처 재생으로 만든다.

### 완료 기준

- 규칙 대 ML 비교표 1개.
- 현미경 화면 M3(캡처 재생).

## D주 (11/18 ~ 11/23) 마무리와 공개

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | 이 시스템에서 AI는 무엇을 잘하고 어디서 틀리나 (A~C주 채점표·비교표 종합) |
| 2 | 같은 모델을 압축(Q4)하면 판단이 얼마나 바뀌나 (7B 원본 대 Ollama 압축본. 정밀도 진단 결과로 답하고, 층별 화면 M5는 선택) |
| 3 | (선택) AI가 도구를 쓴다는 것은 무엇인가 (에이전트) |

### 할 일

- 정적 내보내기로 공개 링크를 만들고, 최종 문서와 시연을 정리한다(캡처 파일은 층별로 쪼개서 담는다. 파일 하나 100MB 제한 때문).
- 설계 그림을 정리한다(Fig 2에 explorer·microscope 추가, Fig 3·4 갱신).
- tool calling(에이전트)과 에이전트 대 고정 프롬프트 비교표는 선택이다.
- 현미경 M4(Decode, KV 캐시 화면)와 M5(설명 정리, 원본 대 압축본 대조)는 시간이 남을 때만 한다.
- A~C주의 채점표·비교표를 한 페이지에 모은다.

### 완료 기준

- 공개 링크, 최종 문서, 시연.
- A~C주 채점표·비교표 모음.
- 압축(Q4) 영향 요약표(정밀도 진단 결과: float32 몸통 기준 로그확률 차이).
