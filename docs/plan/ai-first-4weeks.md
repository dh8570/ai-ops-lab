# AI 우선 4주 계획 (2026-10-27 ~ 11-23)

이 문서가 4주 계획의 **유일한 원본**이다. 다른 문서(CLAUDE.md, PROJECT_CONTEXT.md, README.md)는 이 문서를 가리키기만 한다.
용어는 [docs/glossary.md](../glossary.md)에 쌓는다.

## 목적

배우려는 것 세 가지:

| # | 질문 |
| --- | --- |
| 1 | 어떤 문제를 AI로 푸는가 |
| 2 | AI는 이 프로젝트에서 어떻게 동작하는가 |
| 3 | 데이터는 어디에 저장해 어떻게 쓰는가 |

서비스 완성도가 목적이 아니다. **AI 적용과 그 근거(채점표, 비교표)가 결과물이다.**

## 원칙

- AI 우선. 인프라 작업은 AI 단계를 막을 때만 최소로 한다.
- 매주 시작할 때 그 주의 "AI 질문 세 가지"를 정하고, 그 주의 일이 그 질문을 향하는지로 판단한다.
- 매주 결과물에 채점표나 비교표가 하나 이상 들어간다.
- 모르는 용어와 내용은 질문하며 배운다. 새 용어는 docs/glossary.md에 쌓는다.
- 민감 정보 제거(마스킹)와 에이전트 안전장치는 Opus, 나머지는 Sonnet.
- 탐험 사이트는 실제 파이프라인의 실행 기록을 보여 주는 뷰어이며, 사이트에만 있는 로직을 만들지 않는다. 화면의 값에는 증거 등급(실측, 계산, 설명용, 미확인)을 붙인다.
- 모델은 두 길로 쓴다: Ollama(서버 GPU, Q4 압축, 운영용: 장애 알림 요약)와 현미경 엔진(VM CPU, bf16 원본, 학습용: 모든 층의 값을 기록). 현미경 엔진은 알림 경로에 쓰지 않는다.

## A주 (10/27 ~ 11/2) LLM이 장애를 분석하게 하기

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | LLM은 입력을 어떻게 받아 무엇을 내놓나 (토큰, 읽을 수 있는 양, 속도) |
| 2 | 어떤 정보를 넣어야 원인을 맞히나 (프롬프트, 마스킹의 영향) |
| 3 | AI의 답을 어떻게 믿나 (채점, 지어낸 답, 실패 시 대체) |

### 할 일

- GPU 서버(controller1)에 Ollama를 설치하고, VM↔서버 통로 주소 10.97.0.1:11434에만 공개한다.
- 응답 시간 표를 만든다 (CPU 대 GPU, 콜드와 웜, 입력 크기).
- "알림 먼저, 분석 뒤따름" 여부를 숫자로 결정한다.
- 마스킹(IP, 토큰, 이메일)을 만들고 테스트한다.
- 런북 2~3개를 쓴다.
- LLM 호출과 알림 전송을 감시 루프 밖으로 옮긴다.
- LLM 실패 시 기본 템플릿을 보낸다.
- 장애 시나리오 5개로 채점표를 만든다.
- 파이프라인 탐험 사이트 S0(문장 → 토큰화 → 읽기·쓰기 → 복원, 실측)를 만든다.

### 완료 기준

- 장애 알림에 요약·원인 후보·확인 항목이 붙는다.
- Ollama를 멈춰도 기본 알림이 간다 (합격 시험 항목으로 자동화).
- 감시 루프가 AI 호출로 멈추지 않는다.
- 채점표 1개.

## B주 (11/3 ~ 11/9) AI가 쓰는 데이터와 RAG

### AI 질문

| # | 질문 |
| --- | --- |
| 1 | AI용 데이터는 어디에 어떤 모양으로 저장하나 |
| 2 | 임베딩과 벡터 검색은 어떻게 비슷한 것을 찾나 |
| 3 | 찾아 넣은 지식이 답을 얼마나 좋게 하나 |

### 할 일

- 기존 Postgres에 pgvector를 추가한다.
- 테이블을 만든다: 장애 / AI 분석(프롬프트, 답, 모델, 시간, 토큰 수) / 사람의 판정(맞음·틀림) / 런북 조각과 벡터.
- 런북과 과거 장애를 검색해 프롬프트에 넣는다.
- RAG 전후를 비교한다.
- 현미경 엔진(M2: Qwen2.5-7B를 VM CPU에서 bf16으로 직접 계산하고 모든 층의 값을 기록·검증)과 층별 화면(M3·M4: 임베딩, Prefill, 첫 토큰, Decode, KV 캐시)을 만든다.

### 완료 기준

- RAG 있음 대 없음 채점 비교표.
- 저장 데이터 설명 문서.

(A·B주까지만 해도 세 질문 모두에 답이 나온다.)
