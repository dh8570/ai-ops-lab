# 용어집

새 용어가 처음 나오면 한 줄을 추가한다. "처음 나온 주"는 그 용어를 본격적으로 쓰는 주다 (계획: [docs/plan/ai-first-4weeks.md](plan/ai-first-4weeks.md)).

| 용어 | 쉬운 뜻 | 이 프로젝트에서 | 처음 나온 주 |
| --- | --- | --- | --- |
| LLM | 엄청나게 많은 글을 읽어 두고, 앞 글을 보고 다음 말을 이어 쓰는 척척박사 | 장애 로그와 런북을 읽고 원인 후보와 확인 항목을 써 주는 분석가 | A |
| Ollama | 내 컴퓨터에서 척척박사를 빌려 쓸 수 있게 해 주는 도서관 사서 | GPU 서버(controller1)에서 돌며 VM에 10.97.0.1:11434로만 응답함 | A |
| 토큰 | 글을 AI가 읽기 좋게 잘라 놓은 낱말 조각 | 한 번에 읽을 수 있는 양과 응답 시간이 이 조각 수에 따라 달라져 로그를 몇 줄 넣을지 정하는 기준이 됨 | A |
| 토크나이저 | 글을 낱말 조각(토큰)으로 자르고, 조각 번호(id)와 글로 되돌리는 표를 가진 가위 | 탐험 사이트가 Qwen2.5-7B-Instruct의 tokenizer.json을 그대로 써서 입력이 몇 조각이 되는지 잼 | A |
| 바이트 조각 | 한글 한 글자는 컴퓨터 안에서 바이트 3개인데, 그 3개가 두 조각에 나뉘어 담긴 상태 | 이 토크나이저는 글자가 아니라 바이트 단위(ByteLevel)로 자르므로 한 글자가 여러 토큰으로 갈라질 수 있고, 탐험 사이트가 점선 칩으로 표시함 | A |
| 스트리밍 | 답을 다 쓸 때까지 기다리지 않고 쓰는 대로 조금씩 받아 보는 것 | Ollama의 조각 도착 시각을 재서 올리기·읽기·쓰기 시간과 조각별 간격을 그림 | A |
| tok/s | 1초에 토큰을 몇 개 쓰는지, 필기 속도 | eval_count ÷ eval_duration으로 계산해 응답 시간 표의 기준으로 삼음 | A |
| num_ctx | 책상 위에 한 번에 펴 놓을 수 있는 종이의 한도 | 탐험 사이트에서 2048/4096/8192 중 골라 질문과 답이 들어갈 수 있는 토큰 수의 한도를 정함 | A |
| temperature·seed | 답을 고를 때의 주사위 흔들림 정도(temperature)와 주사위 시작 번호(seed) | 같은 조건에서 답이 얼마나 달라지는지 보려고 탐험 사이트 옵션으로 둠 | A |
| logprobs | AI가 각 조각을 고를 때 후보마다 매긴 확률(로그 값) | Ollama 0.40.2가 내주는지 /api/probe로 확인함(내주면 조각별 후보를 볼 수 있음) | A |
| 콜드/웜 | 아침에 막 시동 건 차는 느리고, 달리던 차는 바로 나가는 것 | 모델을 처음 불러올 때(콜드)와 이미 올라와 있을 때(웜)의 응답 시간을 따로 잼 | A |
| 프롬프트 | AI에게 주는 업무 지시서와 참고 자료 묶음 | 장애 요약, 최근 로그, 런북을 어떤 순서로 담아 보낼지가 답의 품질을 좌우함 | A |
| 마스킹 | 서류를 남에게 보여 주기 전에 민감한 부분을 검은 펜으로 지우는 것 | IP, 토큰, 이메일을 LLM에 보내기 전에 지움 (Opus로 설계·구현) | A |
| 환각(지어낸 답) | 모르면서 아는 척 그럴듯하게 둘러대는 것 | 로그에 없는 원인을 단정하는 답을 채점표로 잡아냄 | A |
| 채점표(평가 세트) | 같은 문제를 여러 번 내서 점수를 매기는 시험지 | 장애 시나리오 5개로 AI 답이 맞는지 점수를 매기고, 이후 주마다 같은 표로 비교함 | A |
| 임베딩 | 글의 뜻을 지도 위의 좌표 한 점으로 바꾼 것 | 런북 조각과 과거 장애를 좌표로 바꿔 저장함 | B |
| 벡터 검색 | 지도에서 내 위치와 가까운 가게부터 찾는 것 | 지금 장애와 뜻이 가까운 런북과 과거 장애를 찾아옴 | B |
| RAG | 시험 볼 때 관련 참고서 쪽수를 먼저 찾아 펴 놓고 답하는 것 | 찾은 런북과 과거 장애를 프롬프트에 붙여 답이 좋아지는지 전후를 비교함 | B |
| pgvector | 기존 서랍장(Postgres)에 좌표 전용 칸을 달아 주는 부품 | 새 DB 없이 기존 Postgres에 임베딩을 저장하고 검색함 | B |
| Isolation Forest | 남들과 확 다른 별난 점을 금방 골라내는 방식의 이상 탐지 | 창 단위 특징에서 평소와 다른 창을 찾아 규칙과 비교함 | C |
| 특징(feature) | 사람을 키, 몸무게처럼 숫자 몇 개로 설명하는 것 | 1분 창의 요청 수, 에러율, p95 같은 숫자를 ML에 넣을 재료로 저장함 | C |
| 잘못 울림/놓침(오탐/미탐) | 불이 안 났는데 울리는 화재경보와, 불이 났는데 조용한 화재경보 | 규칙과 ML을 비교할 때 세는 두 가지 실수 | C |
| 에이전트 | 시키는 대로 쓰기만 하지 않고 스스로 필요한 자료를 찾아보는 조수 | 로그 조회와 상태 확인을 스스로 골라 호출해 원인을 좁힘 | D |
| tool calling | 조수가 "이 서랍 좀 열어 보겠습니다" 하고 정해진 도구만 요청하는 것 | 읽기 전용, 허용 목록 안의 도구만 AI가 부를 수 있게 함 | D |
| 워킹 스켈레톤 | 뼈대부터 끝까지 이어 걸어 다니게 만든 뒤 살을 붙이는 방식 | 앱 → 로그 → 감지 → 알림 흐름을 먼저 연결해 둔 이 프로젝트의 진행 방식 | 0~2주차 |
| 합격 시험(E2E) | 부품 하나가 아니라 출발부터 도착까지 실제로 달려 보는 종합 시험 | 장애를 일으켜 알림이 제때 한 번만 가고 해소되는지 자동으로 확인하는 스크립트 | 0~2주차 |
